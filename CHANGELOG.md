# Changelog

All notable changes to Copilot are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and releases follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) with tags `vMAJOR.MINOR.PATCH`. One version covers the server image, the Linux and Android apps, and the web app they bundle: the root `Cargo.toml` (`workspace.package.version`) and `apps/native/package.json` hold it, and a release tag must name it.

Every release lists what an operator must do under "Upgrade Notes": schema changes, new or changed environment variables, and whether the release may be skipped. The steps of an upgrade are in [docs/self-hosting.md](./docs/self-hosting.md#upgrades). `make test-upgrade` and CI upgrade a database written by the previous release tag with the current code and use it ([scripts/check-upgrade.sh](./scripts/check-upgrade.sh)).

## [Unreleased]

The first release, planned as `v0.1.0`. It has no predecessor, so there is nothing to upgrade from.

### Added

- **Server:** one Rust binary (axum) that serves the API under `/api` and the web app, and a `migrate` binary that applies lib-rustauth's `auth` migrations, then Copilot's, and grants the server's role (`copilot_server`) the rows of every table. Postgres 18 holds everything, file bytes included.
- **Providers:** OpenAI-compatible connections (presets `openai`, `gemini`, `openrouter`, `ollama`, `custom`) and Anthropic connections (`anthropic`, `custom`), with streamed answers, reasoning, tool calls, images, PDFs, and audio where the model takes them. API keys are sealed with AES-256-GCM under `SECRET_KEY`. Model lists with capabilities from the provider's metadata or the preset's defaults; a `gemini` connection's models get their context window, output limit, and thinking flag from Google's native model list.
- **OpenAI Responses API:** each OpenAI-compatible connection picks the API its answers use, Chat Completions or Responses (`POST {base}/responses` with `store: false`, reasoning replayed from its encrypted items to the model that wrote them; after a chat switches models, earlier answers go back as plain text and calls), in the add form and on the connection's page. The `openai` preset uses Responses by default, so GPT-6 models call tools, GPT-5.4 and later reason while tools are on, and reasoning summaries show; switch such a connection to Chat Completions for audio models, which the Responses API does not serve yet (their audio switches are locked on Responses). The `custom` preset stays on Chat Completions and can opt in; the `gemini`, `openrouter`, and `ollama` presets use Chat Completions. The model list stays `GET {base}/models`. `tools/fake-llm` speaks the Responses API too, and the smoke and browser tests run on it.
- **MCP OAuth sign-in:** a tool server's authentication is none, a bearer token or headers, or a sign-in. For servers that require OAuth (MCP authorization, revision `2026-07-28`), Sign in on the server's page opens its sign-in page (in the system browser from the Linux and Android apps); Copilot discovers the authorization server, uses a client id you entered, its own client document, or dynamic registration, signs in with PKCE, and keeps the tokens sealed on the server, refreshing them before they expire and when the server refuses one. The server's page and the list show Signed in, Expired, or Needs sign-in, with Sign out. Needs `PUBLIC_URL`.
- **stdio MCP servers:** an administrator may add a program on the server that speaks MCP over stdin and stdout (Settings, Tool servers, Add, Program on this server), when `MCP_STDIO_ENABLED` is on. Copilot runs it without a shell, with only the environment variables entered for it (stored sealed, shown by name only), in its own folder under `MCP_STDIO_DIR`, one process per chat turn, killed after a 30-second start timeout or when the turn ends together with what it started; its stderr goes to the log at debug level (`mcp.stdio.stderr`). The setting and the owner's administrator role are checked again before every start. The whole command shows while it is entered, in a confirmation before it is saved, on the server's page, and when its tools are reviewed. `GET /api/capabilities` tells the web app whether to offer it. The self-hosting guide has recipes for a derived image with a runtime, the server outside Docker, and the bridge container, and the resource limits to set. `fake-llm --stdio` serves its tools over stdio for the smoke test.
- **Chats:** streaming that survives a closed tab, reattaching from any device, stop, regenerate, retry, edit and resend, Continue, search, unread and approval dots.
- **Projects:** instructions, files, a default model and reasoning level, tools, and schedules shared by every chat in the project; Save as project.
- **MCP tools:** remote servers over Streamable HTTP (both protocol eras) with a bearer token or headers, Off, Ask, or Auto per tool, approval cards, and a review after a server changes its tools.
- **Schedules:** cron rules in the owner's time zone, fired by the server's clock; the model may propose a schedule, which the owner approves.
- **Voice:** push to talk (16 kHz WAV clips up to 5 minutes) for models that take audio, and spoken replies saved as WAV files for models that return audio. None for Claude models.
- **Accounts:** lib-rustauth `v0.1.0` (pinned by commit): the first account is the administrator, registration is closed by default, sessions, lockout, and per-address limits.
- **Apps:** the installable web app, a Linux app (`.deb` and AppImage, glibc 2.39 or newer), and an Android app (arm64 APK), attached to each GitHub Release with `SHA256SUMS`.
- **Deployment:** `deploy/compose.yml` (Postgres, `migrate`, the server on `127.0.0.1:3000`), the image `ghcr.io/host39/copilot:<version>` published on each release tag, `deploy/backup.sh` for nightly dumps with retention (with a crontab line and a systemd timer), and the self-hosting guide (reverse proxy, private network policy, Ollama, a stdio MCP server behind a bridge, upgrades, backups).

### Upgrade Notes

- **From nothing:** install with [docs/self-hosting.md](./docs/self-hosting.md#install), with `COPILOT_IMAGE=ghcr.io/host39/copilot:0.1.0`. Keep `deploy/.env`: a different `SECRET_KEY` makes every stored provider key and tool server header unreadable.
- **Schema:** the migrations in `packages/database/migrations/` become fixed with this release. Later releases change the schema only with new migrations, which `migrate` applies on the next `up`.
- **Tool server sign-in:** set `PUBLIC_URL` (the `https` address people open Copilot at; `http://localhost` for development) to turn it on; without it the server starts as before and sign-in answers that it is not set up. `OAUTH_CLIENT_METADATA` (default `true`) can be set to `false` on an install the sign-in servers cannot reach. The migration `add_tool_server_sign_in` adds `tool_servers.auth_mode` (existing servers with a token or headers become `headers`, the others `none`) and the OAuth columns, and the table `oauth_flows`. Clients that create or update tool servers without `authMode` keep working: credentials imply `headers`.
- **stdio tool servers:** off unless `MCP_STDIO_ENABLED=true`, which also needs `MCP_STDIO_DIR` (an absolute folder the server's user may write; without it the server stops at start). The default image has no Node.js or Python: see the self-hosting recipes. The migration `add_stdio_tool_servers` adds `tool_servers.transport` (existing servers become `http`), `command`, `args`, `env_sealed`, and `cwd`, and makes `url` nullable for stdio servers; tool server responses now carry `transport`, a nullable `url`, and `stdio`, and `url` is optional in `POST /api/tool-servers`.
- **OpenAI connections:** the migration `add_provider_api` gives every OpenAI-compatible connection an API: `responses` for the `openai` preset, `chat_completions` for the others. On a development database with an `openai` connection that served audio models, switch it back to Chat Completions in its settings.
- **Development databases** created before the first release (from this branch) may have applied migrations that were edited before the release; recreate them with `make clean` and `make setup` if `migrate` reports a changed checksum.
