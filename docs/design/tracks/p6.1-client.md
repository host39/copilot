## Sub-Steps

- [x] P6.1C.1 Web, the medium findings. **Sheets** (`components/Dialog`): a backdrop tap counts only when the press and the click both landed on the `<dialog>` itself (`isBackdropTap`, `useBackdropTap`, used by `Modal` and `ConfirmDialog`), so selecting text and releasing past the sheet's edge no longer closes it. A form inside a `Modal` marks itself dirty (`useModalDirty`); then Escape, a backdrop tap, or Close shows "Discard your unsaved changes?" with Keep editing (focused) and Discard, and Escape again keeps editing. The chat instructions drawer and Rename Project use it. **Drafts** (`components/Chat/drafts.ts`): the composer keeps its text and its ready files per chat (`chat:<id>`) and per new chat screen (`new:<project id>`; the new chat screen keeps one draft whatever project is picked, so the text follows a change of project), and a new chat keeps its model, reasoning, tools, and Speak replies; everything is restored on mount and dropped on a successful send. An upload still running when the composer goes is deleted once it finishes. **Scrolling** (`routes/chat/page.tsx`): a new message moves the view only while the user is within 80 px of the end (`nearBottom`), or right after their own send, edit, regenerate, retry, or Continue; a round Jump to latest button shows while they read further up. **First-run models step** (`routes/welcome`): above 20 models (`AUTO_ENABLE_MAX`, core's `MODEL_AUTO_ENABLE_MAX`) it says none is on yet and to turn on at least one below; the disabled Start chatting button is described by "Turn on a model to start." Tests: `dialogs.test.ts` (backdrop taps, close requests), `composer.test.tsx` (draft keys, ready files only, dropped when emptied, restored text, at most `DRAFTS_MAX`, forgotten on sign-in and sign-out), `chat-actions.test.tsx` (`nearBottom`), `welcome.test.tsx` (`modelsNote`).

- [x] P6.1C.3 Native shells. **Navigation guard** (`src-tauri/src/navigation.rs`): a plugin's `on_navigation` allows only the bundle's origins (`tauri://localhost`, `http://tauri.localhost`, and the dev server under `tauri::is_dev()`); every other navigation is cancelled, and an `http` or `https` one is handed to the opener (the system browser). The origin-blind microphone answer can therefore only reach the app. **Downloads** (`src-tauri/src/files.rs`, `apps/web/src/components/Files/save.ts`): native builds send a download's bytes to the app command `save_file` (raw IPC body, the name percent-encoded in `x-file-name`), which opens the system's save dialog (`tauri-plugin-dialog`; Android's document picker returns a `content://` URI) and writes through `tauri-plugin-fs`'s `open`, which handles both paths and Android URIs. The capability grants only `allow-save-file` (declared through the app manifest in `build.rs`), no `fs` or `dialog` command; a failure throws a `LocalError` that says which file could not be saved and why, shown where the download button is. **Release signing**: `build.gradle.kts` signs the release build type with the keystore at `ANDROID_KEYSTORE_PATH` when set, else with the debug key; `native.yml` decodes `ANDROID_KEYSTORE_BASE64` only on `v*` tags (and fails the tag build without it), passes the passwords only to tag builds, requires a non-debug signer on tags and the debug signer otherwise, and writes the signer's SHA-256 to the run summary. `apps/native/README.md` has a Release Signing section (create the keystore, the four secrets, publishing the fingerprint). Tests: Rust unit tests for `allowed`, `external`, and `file_name` (decoding, path parts, control characters, fallbacks); `config.test.ts` (capability list, no `fs` or `dialog` commands, app manifest, plugins and crates, the guard's rules, Gradle signing from the environment); `workflow.test.ts` (keystore step on tags only, passwords only on tags, signer checks); `save.test.ts` (bytes and name to `save_file`, a cancelled dialog, a failure's message).
- [x] P6.1C.4 CI. **Smoke binaries**: the smoke test is a step of the Rust job on the binaries it just built, so the `smoke-binaries` artifact and the separate job are gone and no pull request (a fork's included) leaves binaries in the run list. **Base images**: the Dockerfile's `node:22-slim`, `rust:1-slim-bookworm`, and `debian:bookworm-slim` and the `postgres:18.1` of `deploy/compose.yml` and the CI service are pinned by digest (looked up through the registry mirrors, since Docker Hub rate-limited this host); Dependabot's `docker` and `docker-compose` ecosystems propose new digests. The developer's `docker-compose.yml` keeps its tag, so pulling this branch never recreates a running local database. **Footprint budgets**: `scripts/footprint.sh` measures the release `server` and `migrate` (Rust job), the gzip size of the JS and CSS that `index.html` loads (lint job), and the image (`image.yml`), adds them to the run summary, and fails above its budgets (server 36 MiB, migrate 9 MiB, first load 170 kB gzip, image 55 MB as `docker image inspect` reports it on the runner; measured 30.9 MB, 7.2 MB, 152.8 kB, and 44.5 MB, so growth needs a deliberate change).

## Decisions

- **Drafts stay in memory.** Nothing a user types reaches the disk, every draft is forgotten when the session changes (sign in, sign out, another tab), and at most 20 of each kind are kept. A reload starts empty; that is the trade for never leaving a half-written message in storage on a shared computer.
- **Uploads that outlive the composer are deleted.** A file still uploading when the user leaves a chat cannot join the kept draft, so it is deleted when it finishes instead of staying behind as an unsent attachment.
- **A dirty sheet asks; a clean one closes at once.** Only forms with typed text (the instructions drawer, Rename Project) mark themselves dirty; pickers and confirmations close as before. The question is inline in the sheet, not a second dialog, so no nested `<dialog>` events reach the sheet's own handlers.
- **The scroll follows the user's own actions.** Sending, editing, regenerating, retrying, and Continue all start an answer the user asked for, so they move to the end; a tool approval does not, because the card already sits at the end.
- **The chat's tab shows the name the user gave.** The `document-titles` rule's title case is for fixed labels; names of chats and projects are shown as typed, as the project page already did.
- **Downloads go through one app command, not the plugins' commands.** Granting `fs:allow-write-file` and `dialog:allow-save` would let any script in the web view write wherever a scope allows; `save_file` always asks with the save dialog, writes only where the user chose, and needs one permission.
- **The HTTP plugin scope stays open (skipped).** The user picks the server at run time, so the scope can only be narrowed by a command that adds a runtime capability for the chosen origin; that command would be callable from the same web view a hostile script would run in, so it protects only behind a native confirmation for every new server. And the opener, which must open any `http` or `https` link from a chat, is an equal exfiltration path for such a script. The barriers that matter are already in place: the CSP allows no inline or remote script, chat output renders without raw HTML, and the new navigation guard keeps remote pages out of the window. Revisit with a confirmed runtime capability if the app ever loads third-party content.
- **Zod mini is not adopted (skipped).** The 27 kB gzip is classic Zod's shared core. `@rustauth/contracts` (re-exported from `@copilot/contracts`) and the web's own form schemas (sign-in, setup, providers, projects, schedules) also use the classic API, so moving only the contract schemas would leave classic Zod on the first load. The full move spans lib-rustauth's package (a release and a pin bump) and every form schema; it belongs to P6.3's footprint work if the budget asks for it.
- **Tags fail without the release key.** A tag is a release; a debug-signed release APK cannot be updated in place and cannot be traced to this repository, so the workflow refuses to build one rather than ship it.
- **Footprint budgets sit above today's sizes.** They stop silent growth now; the server checkout's footprint work (release profile, runtime image) and P6.3 tighten them once the smaller sizes are measured.
