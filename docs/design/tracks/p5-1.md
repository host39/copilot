## Decisions

- **Minimal capability, not `core:default`.** The page uses only the HTTP plugin, the opener's link handler, `onBackButtonPress`, and `exit`. `core:default` would also let the page manage windows, webviews, menus, trays, paths, and events; none is needed. `exit` is not in `core:app:default`, so it is granted alone. Channel reads of streamed bodies need no permission (Tauri exempts `plugin:__TAURI_CHANNEL__|fetch`). If the device test finds a missing permission, add that one permission, not `core:default`.
- **Links open through the opener plugin's own handler.** Its init script opens `target="_blank"` links (every link in a chat, `components/Chat/Markdown.tsx`) with `open_url`; the capability limits that to `http`, `https`, and `mailto` (the plugin's default also allows `tel:` and revealing files, both dropped). The web code needs no change.
- **No `devCsp`.** Tauri uses the CSP only for bundled assets; on the desktop `tauri dev` loads the dev server directly, and on Android it proxies it, neither with a CSP header. A dev policy would protect nothing and would need the live-reload socket.
- **The plugin's `cookies` and `system-proxy` features are off.** The API uses bearer tokens, so a cookie jar would only keep what a server sets; `system-proxy` reads macOS and Windows proxy settings, which Linux and Android builds do not use. `reqwest` 0.12 with `rustls-tls` uses ring, which cross-compiles for Android with the NDK alone.
- **The Android back listener is Android only.** Tauri's `app` plugin handles `register_listener` only through its Android plugin, so on Linux the call failed and logged `web.back.listen.failed` on every start; `isAndroid()` checks the user agent inside the native app.
- **Changing the server stays one tap away.** The Connect screen was reachable only on first launch, so a user whose server moved had to clear the app's data. The server now shows on every signed-out screen with Change; changing it signs out (as `saveServerUrl` already did), and the Connect screen offers to keep the current one.
- **The Android project is committed and customized.** Release APKs are signed with the SDK's debug key, per the owner's decision (debug-signed arm64 APK for sideloading), so `tauri android build --apk --target aarch64` gives an optimized, installable APK without a keystore; a `--debug` build would instead be unoptimized, debuggable, and allow cleartext in the WebView. Android 15 enforces edge to edge for apps targeting SDK 35 and later (the template targets 37) and wry does not apply window insets, so `MainActivity` pads the WebView's parent by the system bar, display cutout, and keyboard insets, which also keeps the composer above the keyboard. Both changes are in the README for anyone who regenerates the project. The template's Android TV launcher entry and FileProvider stay as generated.
- **Identifier `com.host39.copilot`; `in.host39.copilot` only as the application id.** Tauri derives the Kotlin package, the Gradle namespace, and the JNI symbol names from `identifier` (`tauri-build` writes `TAURI_ANDROID_PACKAGE_NAME_PREFIX` without escaping keywords), so `in.host39.copilot` cannot be the identifier. The README's recipe keeps the identifier, edits `applicationId` in `app/build.gradle.kts`, and optionally sets the Linux identifier in `tauri.linux.conf.json`.
- **Icons come from the web icon.** `tauri icon apps/web/public/icons/icon.svg` writes the desktop PNGs, `.ico`, `.icns`, and the Android launcher icons; the iOS and Windows Store files it also writes are deleted until those platforms ship.
- **Version 0.1.0.** Android's version code is derived from the version (`0.1.0` gives 1000), and 0.0.0 would give 0.
