## Decisions

- **Stale tool lists keep their fetch time.** `stale` sets the stored list's `ttl_ms` to 0 instead of moving `tools_fetched_at`, so Settings still shows when the list was fetched and the list stays as the fallback when listing again fails. A fresh listing replaces it as usual.
- **`can_reason` is the capability, not a level.** It is true for every model with the `reasoning` capability (after overrides). Only the Anthropic adapter reads it today; OpenAI-compatible dialects have no "show the default reasoning" switch.
- **Shutdown lets runs finish first.** The spec had the root token fire on the signal; runs now get `SHUTDOWN_GRACE_SECS` (5) to finish on their own (a short answer completes instead of being cut), then the root token fires as before. Both waits count from the signal, so the second call (from `ApiContext::close`) only waits for what is left.
- **`SERVER_STOPPING` is a `422`.** `DomainError` has no `503` variant, and the other registry refusals (`CHAT_BUSY`, `TOO_MANY_RUNS`) are `422` too.
- **Resuming needs no run id.** A `seq` above the running turn's last one cannot be from it, so the stream starts over; a lower `seq` from an earlier run cannot be told apart, and the client's reducer (P3.3) restarts from the beginning when the first event names a message it does not hold.
- **Recovery does not move the chat.** `recover` changes only the messages, so a restart turns no chat unread and reorders nothing.
