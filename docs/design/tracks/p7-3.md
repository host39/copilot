# P7.3: Built-In stdio MCP Servers

Branch: `claude/copilot-project-planning-6y3fep` (shared with other checkouts; merged before each push). Base: P7.2 at `8a40d6a`. Roadmap step: `p7.3`.

v0.1 reached local MCP servers only through a bridge container that turns stdio into Streamable HTTP. This step lets an administrator register a program on the API host that speaks MCP over its stdin and stdout, under the hardening rules the spec has carried since v0.1 ("Later: stdio Servers", now [stdio Servers](../copilot.md#stdio-servers)).

## Decisions

- **The transport is fixed at creation.** A server is `http` or `stdio` for life; to change it, add another server. This keeps OAuth, headers, and the URL rules out of stdio entirely (a stdio server's `auth_mode` is always `none`; the database `CHECK` enforces it).
- **An absolute program path.** The process starts with an empty environment, so there is no `PATH` to look a bare name up in; `npx` is refused with a message that asks for `/usr/local/bin/npx`.
- **Arguments are kept exactly** (no trimming, no splitting, no expansion); each is passed as one `argv` entry. Limits: 64 arguments of 4,096 characters, 64 variables (names of letters, digits, and `_`), no NUL characters anywhere.
- **The environment is a secret.** Values are sealed in `env_sealed` (bound to the row like every other sealed column) and never come out; responses list the variable names only. Saving the same values again keeps the sealed bytes, so an unchanged form does not count as a new program.
- **The working directory is a relative path under `MCP_STDIO_DIR`** (plain names joined by `/`, no `.` or `..`), the server's id by default. The adapter makes it owner-only (`0700`) on first use and refuses it when symbolic links lead outside the base.
- **A changed program is a new server for review purposes**, as a changed URL is: the protocol version is forgotten, the tools are listed again before a turn offers them, and every tool asks until the review. The listing guard compares the command, arguments, sealed environment, and directory.
- **Who may do what.** Adding a stdio server, or changing its program, needs an administrator while `MCP_STDIO_ENABLED` is on (`FORBIDDEN` 403, `STDIO_DISABLED` 422). The owner may still rename, disable, or delete it after a demotion. Turns never list or offer a stdio server unless the caller may run it, and `ToolService::endpoint` refuses it otherwise. Servers belong to their owner, so a stdio server is only ever selectable in its administrator's own projects, chats, and schedules (the composite foreign keys already ensure this).
- **The gate.** Core puts a `SpawnGate` into every stdio endpoint; the adapter calls it right before each process start (each lifecycle attempt is a new process, so each passes it). It reads `MCP_STDIO_ENABLED` and the owner's account as stored now (`Accounts::active`, one query), so a demoted or disabled administrator's server stops starting at once, even within a run that already started.
- **Process lifetime.** One process per server per run, started on the first call (or for a listing, which ends it again). A process gets `MCP_STDIO_START_TIMEOUT_SECS` (30) to finish the MCP handshake, or it is killed. The process leads its own process group. When the run's session closes, stdin closes, then `SIGTERM`, then `SIGKILL` (2 seconds apart), and whatever is left of the group is killed; a session that is dropped instead kills the group at once. rmcp's own `TokioChildProcess` was not used for the shutdown: when the program exits on its own it forgets the group, so children the program started outlived it (a test proved this).
- **stderr** goes to `mcp.stdio.stderr` at `debug` (the program's own text, which may echo tool arguments, so not at `info` per the logging rules), one event per line with control characters as spaces, lines cut to 1,024 bytes, at most 200 lines per process; the rest is read and counted (`mcp.stdio.stderr-dropped`), so a chatty program never blocks on a full pipe.
- **Responses over stdio are capped** like HTTP ones: a line over `MCP_RESPONSE_MAX_BYTES` ends the connection.
- **`GET /api/capabilities`** (`stdioServers`: the setting is on and the caller is an administrator) rather than a field in `/settings`, which holds the caller's own preferences. The web app offers the stdio fields only when it says so; the server checks again on every write.
- **The web form.** Arguments are one per line, each kept exactly (blank lines are dropped, so an empty argument needs the API). The command line is shown whole (wrapped, never cut, in `.program-line`) while the program is typed, in a confirmation before it is saved (the test right after starts it), on the server's page, and on the review prompt. Quotes in that line only show where an argument starts and ends; nothing goes through a shell. Environment values are entered like header values (hidden until shown) and never come back: the page lists the names, entering variables replaces them all, and a switch removes them.
- **Responses keep `url`.** `ToolServerResponse.url` became nullable (`null` for a stdio server) next to the new `transport` and `stdio`, and `CreateToolServerRequest.url` optional; existing clients that only add HTTP servers keep working.
- **stderr at `debug`.** The task asked for stderr in `mcp.stdio.stderr`; the spec's logging rules keep tool arguments and untrusted text out of `info`, and a program may echo both, so the lines are `debug` (the self-hosting guide says to raise `LOG_LEVEL` while setting a program up). Start, stop, and failures are logged at `info` and `warn` without the program's text.
- **The smoke test runs a real stdio server**: `fake-llm --stdio` (the fake's MCP tools over rmcp's stdio server) as the API's own child, through Test and an approved tool call. The adapter's tests use their own test binary as the program instead, so they need no other build.

## Verification

- `make check` (format, lint, type-check, tests, boundaries), `make test-db`, `make smoke`, and `make e2e` pass locally on Postgres 18.
- The adapter's stdio tests (`packages/mcp/tests/stdio.rs`, the test binary itself as the program, started from a copy whose environment holds `SECRET_KEY` and `DATABASE_URL` like the API's): listing and calls in the server's directory with one process per run; the child's environment is exactly the listed `VISIBLE=yes` (a mutation without `env_clear` fails it); the gate is asked before every start and a refusal starts nothing; a refused start fails every call of the run; no `MCP_STDIO_DIR` and a missing program report `TOOL_SERVER_START`; a program that never answers is killed after the start timeout; the process and a child it started end when the session closes, and when the session is dropped; a call past its timeout is `TOOL_TIMEOUT`; stderr reaches the log at `debug`, 200 lines, the rest counted, escape characters as spaces.
- Core unit tests for the policy, the gate (one account read per start; demoted and disabled owners refused; the setting first), creation and changes (administrators only, no URL or credentials, a changed program needs a review, an unchanged environment keeps its sealed bytes), the endpoint, and turns that never list or offer a stdio server to a non-administrator. `#[sqlx::test]` tests for the columns, the `CHECK`, the readonly omissions, the program round trip, and the listing guard. API tests for capabilities, 403 and 422 refusals, the response shape, the real adapter's start failure, and a demoted administrator.
- `make smoke` runs `fake-llm --stdio` as a stdio server through Test and an approved tool call ("Tool said: over stdio"), with `mcp.stdio.started` and `mcp.stdio.stopped` in the API log.
- Bruno on a throwaway database (`DB_NAME=copilot_b_bruno_p73`, `PORT=3927`, dropped afterwards): 168 requests, 420 assertions, including `09-28` to `09-33` (capabilities for the administrator and another user, another user refused, an administrator's stdio server and its response, a missing program on Test, delete). `make test-bruno` now starts its server with `MCP_STDIO_ENABLED` and an `MCP_STDIO_DIR` in its run folder.
- Footprint: `cargo tree -i aws-lc-rs` finds nothing; the server's graph gains `process-wrap` and `nix` only; the web first load is 153,247 bytes gzip (budget 170,000).
