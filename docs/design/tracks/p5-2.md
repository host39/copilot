## Decisions

- **A workflow-level path filter, not a path-filter job.** `on.push.paths` and `on.pull_request.paths` skip the whole run when neither the shell, the web app it bundles, nor the workflow changed, so no runner starts at all; a slim filter job would start one on every push. GitHub does not apply path filters to tag pushes, so `v*` tags always build, and manual dispatch has no filter. If this workflow ever becomes a required status check, a skipped run leaves the check pending; switch to a filter job then.
- **Pushes build on `main` and `claude/**` only.** Other branches build through their pull requests. A `claude/**` branch with an open pull request builds twice (the push and the pull request have different refs, so the concurrency group does not merge them); that is acceptable while agents push to one branch without pull requests.
- **The Tauri CLI directly, not `tauri-action`.** The CLI version is the one in `apps/native/package.json` (locked by `pnpm-lock.yaml`), the same commands run locally (`make native-lint`, `make android-build`), and no third-party action touches the build. The research note's sketch used the action; its experimental Android mode would add nothing.
- **Bundles: `.deb` and AppImage, no `.rpm`.** The step names those two; `.rpm` stays a local option (`tauri build` without `--bundles`).
- **The checks fail the run before anything uploads.** Linux: the `.deb`'s version equals `package.json`, it depends on `libwebkit2gtk-4.1-0`, and no symbol in its binary needs a glibc newer than 2.39 (Ubuntu 24.04, the floor of both bundles); the AppImage is a 64-bit x86-64 ELF with the type 2 AppImage magic (`AI` and 2 at byte 8). Its runtime is a static-pie ELF, which `file` calls "pie executable", so the check does not require "LSB executable" (the first run failed on exactly that). Android: exactly one APK, signed with a `CN=Android Debug` certificate, native code for `arm64-v8a` only including `libcopilot_native_lib.so`, package `com.host39.copilot`, and `versionName` equal to `package.json`. Each check step writes the artifact names and sizes to the job summary.
- **One file per artifact, not zipped.** `actions/upload-artifact` v7 with `archive: false` names the artifact after the file and downloads it as that file: `Copilot_<version>_amd64.deb`, `Copilot_<version>_amd64.AppImage`, `Copilot_<version>_arm64.apk`. Tag builds keep them 90 days, other builds 14.
- **Each runner signs with its own debug key.** The Android Gradle plugin creates `~/.android/debug.keystore` on a fresh runner, so every CI APK has a different signature and installing a newer one over an older one fails until the old one is uninstalled (which forgets the stored server and session). This is the owner's decision (debug-signed for sideloading) and `apps/native/README.md` says so. A shared debug key in the repository would let anyone who can read it sign an update that takes over an installed app and its session token, so the fix is a release keystore in repository secrets, before any wider distribution.
- **The Cargo cache saves on every branch.** The research sketch saved only from `main`, but development happens on branches and a branch can restore only its own caches and the default branch's.
- **NDK 29 from the runner image.** The image ships NDK 27, 29, and 30; Tauri 2.12's CLI installs 29, and 30 is untested with it (research section 12).
