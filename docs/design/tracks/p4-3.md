## Decisions

- **One crate, one port.** Both formats and the MCP server share port 4010, so a person starts one process. `GET /v1/models` answers Anthropic's shape when the request carries `anthropic-version` or `x-api-key` (Copilot's Anthropic adapter sends both), else the OpenAI-compatible list.
- **rmcp's server features stay in the dev tool.** The task asked for them "as a dev-dependency of this crate only", but a binary cannot use its own dev-dependencies, so they are normal dependencies of `fake-llm`, which is itself dev-only. The workspace's `rmcp` entry stays client-only, product crates may not depend on `fake-llm` (`make boundaries`), the image builds `-p copilot-api -p copilot-database` only, and CI builds `fake-llm` in a cargo invocation of its own, so the server features never unify into the API binaries.
- **Realistic refusals.** The fake checks what the real APIs check (keys, listed models, `anthropic-version`, `max_tokens`, no prefill, tool results answering a call of the previous message, and a replayed `thinking` block carrying the signature the fake gave it, a hash of its text). A replay bug in Copilot then fails against the fake as it would against a paid key.
- **The newest message only.** Copilot leaves refused answers, and failed answers without text, out of the next request, so their prompt merges into the next user message (adjacent user messages merge). The fake reads the last text part of the last user message and the attachments after it (Copilot sends a message's text before its files); otherwise `failed 403` would fail every later turn.
- **`tool` needs a name, then nothing or `{`.** "which tool do you use" stays text; `tool echo` alone calls `echo` with `{}`; text after the name that is not JSON is sent as is, so the client's "Arguments were not valid JSON." path can be tried. Keywords before `tool` (`think`, `slow`) still count; words in the arguments never do.
- **Aliases.** Copilot names tools `<slug>__<name>`; the fake calls the offered tool whose name is the given name or ends in `__<name>`, and an unknown name as written, so "Unknown tool." can be tried too.
- **The reasoner reasons by default.** `fake-reasoner` reasons unless the OpenAI-compatible request says `reasoning_effort: none` (absent counts as on, as reasoning models behave) or the Anthropic request has no adaptive or enabled `thinking`.
- **Audio only when asked.** `audio` on `fake-audio` streams a one-second 440 Hz tone as 24 kHz PCM16 deltas with its transcript only when `modalities` holds `audio` (Speak replies on); otherwise a text reply says to turn Speak replies on. Anthropic has no audio, so `audio` there is plain text.
- **Usage is estimated.** Four characters per token for the request text and the reply; every streamed reply ends with a usage chunk (OpenAI-compatible) or usage in `message_start` and `message_delta` (Anthropic), whatever `stream_options` says.
- **Smoke test settings.** `ALLOW_PRIVATE_NETWORK=all`, `AUTH_REGISTRATION_OPEN=false`, a generated setup token, `SECRET_KEY`, and fake key per run, ports 3091 and 4091 (`SMOKE_API_PORT`, `SMOKE_FAKE_PORT`), refusing to start when either port answers. It never reads `DB_NAME`: the database is always a new `copilot_smoke_<random>`.
- **The smoke job reuses the Rust job's build.** `smoke` needs `rust` and runs its release binaries from an artifact (kept one day), so it needs no Rust toolchain or cache and finishes in about a minute after the Rust job.
