## Interface-Change Requests

None blocking. Suggestions for a later serial step:

- `Dialect::stream_usage` is true for the `openai` preset only. Ollama and vLLM also document `stream_options.include_usage` and send no usage without it, so their answers save no token counts. Turning it on for the `ollama` dialect would fix that for Ollama; `custom` servers vary.
- `LlmRequest::reasoning` is `None` both for a model without the `reasoning` flag and for a reasoning model with no level chosen. Current Claude models think by default with their thinking text omitted, so a Claude chat without a level shows no reasoning. A flag on the request ("the model has `reasoning`") would let the adapter ask for `display: "summarized"` without choosing an effort.
- Core does not check a chat's or project's level against the model's reported `reasoning_levels`. A project set to `off` reaches Claude models that cannot disable thinking (the Models API reports `thinking.types.disabled` unsupported, and the adapter leaves `off` out of their levels), and the provider answers 400. Clamping the level in `context::reasoning` (unsupported `off` becomes no level) would avoid it.
- `DEFAULT_MAX_OUTPUT_TOKENS` (8,192) is tight for OpenAI reasoning models: `max_completion_tokens` includes reasoning tokens, and OpenAI's model list reports no output limit, so a high-effort answer can end at `length` with little text. A larger default for models with `reasoning` (for example 32,768) would help; users can already set the limit per model.

## Notes

Decisions beyond the spec text (for the integrator to write into `docs/design/copilot.md`, Adapter Rules, when Phase 2 merges):

- **OpenRouter reasoning level** goes in its unified `reasoning: {effort}` parameter (OpenRouter documents `none` to `max` there and does not document a top-level `reasoning_effort`); every other OpenAI-compatible dialect sends `reasoning_effort`.
- **PDF parts** go out as `file` parts on every preset when core sends them (core sends them only to models with `pdf`, which defaults on for `openai` and `openrouter` and is otherwise a user override).
- **Replayed reasoning text** goes back under the key it came under on every dialect, as the Replay Rules say. Risk to verify (unconfirmed here): some servers may reject unknown assistant fields (Groq may reject `reasoning` on input messages, and DeepSeek's own API has rejected `reasoning_content` on input for some models); both would reach Copilot as `custom` connections. If that shows up, limit plain-text replay to the current turn or to the `ollama` and `openrouter` dialects.
- **Assistant text parts** are joined with a blank line (they are separate parts: text before and after a tool call, or a transcript).
- **Tool schemas** that are not objects, or lack `type` or `properties`, are completed to `{type: "object", properties: {}}` because Chat Completions servers reject them otherwise (the Anthropic adapter does the same).
- **`<think>` tags** in `content` (servers in raw reasoning mode) are not split out; such text shows as answer text.
- **The deprecated `function_call` delta** is not read (its finish reason still maps to `tool_calls`).
- **Gemini stand-in signature:** on the `gemini` dialect, an assistant step whose calls carry no extra fields (an answer rebuilt from its parts, for example after a model switch) gets `extra_content.google.thought_signature: "skip_thought_signature_validator"` on its first call, the value Google documents for calls it did not generate.
- **Anthropic cache breakpoints:** `LlmRequest` does not mark where the file preamble ends, so the adapter marks the last block of the first user message, which starts with the preamble and stays the same until the window moves; it also marks the system block (it caches the tools with it, and stays warm across chats of one project) and the last block. Three of the four breakpoints the API allows; thinking blocks are never marked.
- **Anthropic reasoning:** no level sends no `thinking` (the model default: current Claude models think with their text omitted); `off` sends `{type: "disabled"}` (listed as a level only for models that report `disabled` supported); `low`, `medium`, `high` send adaptive thinking with `display: "summarized"` and that effort. `xhigh` and `max` are not used (core has no such levels).
- **Anthropic credentials** go in `x-api-key` as the spec says; the research note lists `Authorization: Bearer` as the primary header now, with `x-api-key` "still supported".
- **Anthropic usage:** `input_tokens` is the whole prompt (uncached input plus cache reads and writes), so it compares with OpenAI-compatible `prompt_tokens`; `reasoning_tokens` is not reported (Anthropic counts thinking in `output_tokens`).
- **Anthropic refusals** without an explanation get "The model declined to answer." in the adapter, so `message.finished` never replaces the text with an empty explanation.
- **Tool call ids:** core's rebuilt ids `call_<uuid without dashes>` fit the Messages API `tool_use` id pattern `^[a-zA-Z0-9_-]+$` (the spec's "verify" item; a unit test checks it).
- **Errors:** HTTP 413 reads "The request is too large for this provider." and 529 "The provider is overloaded. Try again in a moment." on every provider; an Anthropic `overloaded_error` event says the same, and `rate_limit_error` maps to `PROVIDER_RATE_LIMITED`. Failure logs carry the provider's `x-request-id` or Anthropic's `request-id`.

Risks to verify live (P3.4):

- A decision after switching to another connection mid tool loop rebuilds the paused Claude answer without its thinking blocks; with thinking on, the Messages API may reject a final assistant `tool_use` that lacks them. The same connection always replays them.
- `display: "summarized"` is assumed accepted on the older adaptive models, where summarized display was the default.
- Gemini thought summaries are not requested: Google documents them only through `extra_body.google.thinking_config.include_thoughts`, which it says cannot be combined with `reasoning_effort`. Gemini 3 and 4 cannot turn reasoning off, so `off` (`reasoning_effort: "none"`) works only on 2.5 models.

Limits checked in P2.B.6 (core keeps its values; all sit inside each provider's documented limit):

| Constant | Value | Provider limits |
| --- | --- | --- |
| `REQUEST_MAX_BYTES` | 32 MiB | Anthropic 128 MB per request on the first-party API (confirmed on the live PDF page; other platforms vary); OpenAI Chat Completions 512 MB of images and 50 MB of PDFs; self-hosted servers set their own |
| `GEMINI_REQUEST_MAX_BYTES` | 20 MiB | Gemini inline data 100 MB per request, 50 MB for PDFs (native API; the compatibility endpoint documents none) |
| `REQUEST_MAX_PDF_PAGES` | 100 | Anthropic 600 pages, 100 when the request's context window is under 1M tokens; Gemini 1,000 pages |
| `DEFAULT_MAX_OUTPUT_TOKENS` | 8,192 | Used only when a model reports no limit: Anthropic reports `max_tokens` for every model, so it never applies there; see Interface-Change Requests for OpenAI reasoning models |
| `AUDIO_OUT_MAX_BYTES` | 300 s of 24 kHz PCM16 | OpenAI `pcm16` output is 24 kHz mono 16-bit |
