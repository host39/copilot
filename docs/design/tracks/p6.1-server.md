# P6.1 Server: Fixes After the Final Review (Rust Crates, API, Database, Docs)

Branch: `claude/copilot-project-planning-6y3fep` (shared with the client checkout, which records its half in [p6.1-client.md](./p6.1-client.md); merged before each push). Base: Phases 0 to 5 as reviewed by the final multi-lens review (correctness, security, layering, UX, footprint), at `48a103a`. Roadmap step: `p6.1-server`.

## Status

Complete: P61S.1 to P61S.8. The review reported 37 findings for the server side and the docs (two high, fifteen medium, twenty low). Several lenses reported the same defect (orphaned chat files three times, the audio token estimate and the download memory twice each), which leaves 33 distinct findings. ## Sub-Steps

- [x] P61S.1 CPU work off the request path (one high, one medium, one low). **PDF pages** (`file/media.rs`): object streams are found in one forward pass that remembers where the current object's dictionary starts (its last `obj`, never before the end of what was already read) and searches `/FlateDecode` only there; at most `PDF_OBJECT_STREAMS_MAX` (4,096) are examined. The reviewer's 2 MiB files that repeat `/ObjStm stream` now take milliseconds. **Worker port** (`ports/worker.rs`): `FileService::upload` measures audio, counts PDF pages, and hashes on `Worker`, which the API implements on Tokio's blocking pool (`helpers/worker.rs`, `BlockingPool`); tests run jobs inline. **Tool diff** (`tool/selection.rs`): `ToolChanges::between` indexes both lists, and the MCP adapter refuses a listing of more than `MCP_TOOLS_MAX` (512) tools with `TOOL_SERVER_TOO_LARGE`. **File blocks** (`conversation/draft.rs`): every `</file` in any case, with white space around the slash, is escaped. Tests: linear time on three crafted 2 MiB patterns, two object streams in one file, a 50,000-tool comparison under a time bound, 512 tools listed and 513 refused (the test server's page size is now an option), the closing tag variants, and the blocking pool running off the runtime thread.
- [x] P61S.2 Request and response I/O (one high, two medium). **Downloads** (`routes/files.rs`): the content route reads the file in pieces of `DOWNLOAD_CHUNK_BYTES` (512 KiB, one `substring` query each through the new `FileRepository::piece`, so no pool connection is held between them) on a task that holds a download slot (`DOWNLOADS_PER_USER` 4, `DOWNLOADS_AT_ONCE` 32) and stops when the client takes no piece for `DOWNLOAD_STALL_SECS` (60); the response carries `Content-Length`. `helpers/uploads.rs` became `helpers/slots.rs` (`Slots::uploads`, `Slots::downloads`). **Upload pace**: a body must arrive within `UPLOAD_GRACE_SECS` (30) plus one second per `UPLOAD_MIN_BYTES_PER_SEC` (16 KiB) received, or the route answers `408 UPLOAD_TOO_SLOW` and the slot frees. **Header timeout** (`helpers/serve.rs`): the server runs hyper's HTTP/1 connections with a timer and `HEADER_READ_TIMEOUT_SECS` (30), with graceful shutdown and the peer address as `ConnectInfo`, instead of `axum::serve`, which runs hyper without a timer. The proxy guide sets `client_max_body_size`, request buffering, and timeouts for nginx and a body limit for Caddy. Tests: a three-piece download with its length and another user's `404` (`make test-db`), the pace on a paused clock (a 1 byte per second body is refused just after the grace period), the server loop answering with the peer address, dropping a client that never finishes its headers, and refusing connections after shutdown.
- [x] P61S.3 Chat files (two medium, one low, and their duplicates). **Orphans** (`chat/service/prepare.rs`): Regenerate, Retry, and Edit pass the chat files only the deleted messages named (attachments an edit dropped, spoken replies, tool result images; `Message::named_files`) to `delete_after` and `replace_tail`, which delete those the chat still owns in the same transaction. Unsent uploads and files moved to a project stay. **Save as project** moves only the files user messages sent (`insert_with_chat` takes their ids). **Audio tokens**: `estimate` counts `TOKENS_PER_AUDIO_SECOND` (32) per second of measured play time, so the window and the meter count clips (9,600 for five minutes). Tests: `orphans` (each file once, a file an earlier message still names, an edit that keeps an attachment), a `make test-db` test of both tail changes (moved, unnamed, and other chats' files stay; the bytes go), the spoken reply test (an edit of the first question deletes its WAV), Save as project leaving an unsent upload and a non-attachment with the chat, and the five-minute clip's estimate.
- [x] P61S.4 Runs (two medium, two low). **Provider delete** stops the caller's runs on that connection first (`RunRegistry::chats_on`; `launch` records each run's connection), so the answer saves as `cancelled`; `MessageRepository::update` no longer rewrites `model_id` and `provider_id` (set once at append), so a cleared foreign key cannot fail the final save, and a failed final save falls back to an `error` answer. **Title race**: the first message writes only the title (`ChatRepository::set_title`, while untitled) and Save instructions clears only the saved instructions (`clear_instructions`, compare-and-set). **Interrupted tool rounds**: `recover()` also marks a `complete` answer with calls that ends its chat as interrupted, so Retry answers it. **Tool servers** (`tool/service.rs`): stale or new servers are listed at most `MAX_PARALLEL_READS` at once; a server whose listing failed is listed again only after `TOOL_REFRESH_BACKOFF_SECS` (300; an update or Test clears the wait) and its stale list is used meanwhile. The first answer's `message.started` names the servers the turn goes without (`unavailable`, optional in the contract and the Zod schema), and the chat shows "Could not reach Docs. This answer has no tools from it." Tests: provider delete during a slow answer (`make test-db`: `cancelled`, model cleared), `set_title` and `clear_instructions` against settings saved meanwhile (`make test-db`), recovery of a stopped round next to a finished one (`make test-db`), the back-off (two servers at once, no listing inside the wait, a settings change and the end of the wait list again), the engine naming unavailable servers, and the web reducer and note.
- [x] P61S.5 Schedules (two medium, two low). **Accounts** (`ports/accounts.rs`): `ScheduleRepository::due` reads Copilot's tables only and takes `skip`; `ScheduleService::fire_due` resolves owners through the new `Accounts` port, which `helpers/auth.rs` implements on rustauth's `AuthService::users` (`Directory`, with the same administrator rule as callers) and queries again without disabled owners (`DUE_PASSES`, 4), so they take no place. **Record in core**: `record` locks the row, applies `Schedule::takes` and `Schedule::recorded`, and writes the result. **Paused runs**: a scheduled run's chat is created at the firing's time; an interactive turn in it (an approval, or a message that skips the calls) and the chat's deletion record how the run ended (`ScheduleService::follow_up`, `RunRecord::follow_up`) while it is still the schedule's latest run and shows as awaiting approval. **Shutdown**: a scheduled run cancelled while the registry drains records `RunOutcome::Ended("The server restarted during the run.")`, an error that does not count toward `SCHEDULE_MAX_FAILURES`; a user's Stop and the time limit still count. ## Decisions

- **Measurement off the runtime through a port.** Core has no Tokio, so CPU-bound work goes through `Worker` (`offload` returns the job's value); the API's adapter is `spawn_blocking`. Uploads compute the clip check, the page count, and the hash in one job before the quota check, so the order of the user-facing errors is unchanged.
- **A pace, not an idle timeout, for upload bodies.** A per-chunk idle timeout lets a client that sends one byte a second keep a slot for the whole overall limit; a pace (grace period plus a minimum average rate) refuses it after 30 seconds while a slow but steady phone upload of 25 MB (about 130 kbit/s) still passes.
- **Downloads in pieces, not a large-object table.** `file_contents.bytes` is already stored uncompressed, so `substring` reads only the TOAST chunks of a piece; no migration was needed. The stall limit ends a download whose client stopped reading, so a slot cannot be held forever.
- **Orphans computed in core.** The repository only deletes the ids core passes (and only those the chat still owns), so the rule "files only the deleted messages named" stays in the domain; a periodic sweep was not added because unsent uploads must stay.
- **Back-off in memory.** One server process runs per install, so failed listing times live in `ToolService` (no migration); a restart lists every due server once more.
- **`unavailable` is optional in the contract.** Older clients ignore it, and the Zod schema accepts its absence, so no client needed to change at the same time.
- **Owners through rustauth's service.** `AuthService::users` reads one query for many ids; a disabled owner's schedules stay due (as before) but no longer take a place: `fire_due` queries again without them, at most four times.
- **Follow-ups need the run's start time on the chat.** The scheduled run's chat is now created at the firing's time, which the schedule already records as the run's start, so a later turn can tell whether its chat is the schedule's latest run without a new column.
- **Session checks every minute, not on revocation events.** Copilot does not learn of sign-outs or revocations inside rustauth; verifying the stream's token every `SESSION_RECHECK_SECS` needs no lib-rustauth change and costs one query a minute per open stream.
- **A `wire` module for the DTO mapping.** Moving `convert` and the serializer out of `routes` lets the run registry use them without a `helpers` to `routes` import; the routes import `wire` like any other caller.
- **`strip` for every release build, LTO for the image only.** CI builds release binaries for the smoke test and the footprint budgets on every push; fat LTO with one codegen unit adds about a minute there, so it lives in a `dist` profile that only the image build uses. `panic = "unwind"` stays (a panicked run's streams end by catching it).
- **Precompression in the image build, not in Rsbuild.** The native shells embed `apps/web/dist`, so `.gz` and `.br` files there would double their bundle; the image's web stage writes them after the build with Node's zlib, and `ServeDir` serves them.
- **Gemini defaults instead of Google's native model list.** The preset's models all read images and PDFs and think; reading the native list for limits is a later adapter feature, and the spec now says so.

## Not Changed

- **P3.4 owner checkpoint** (low): the live checks need the owner's Anthropic, OpenAI or OpenRouter, and Gemini keys (a two-turn tool loop with approvals, a refusal, Speak replies on `gpt-audio`, a WAV clip to Gemini). They stay with P3.4 in the roadmap, unticked, for the owner before the first release.
- **Dummy Argon2 hash at startup** (low): it is lib-rustauth's `AuthService::new` (about 25 ms of a 67 ms start, and the 19 MiB peak). Making it lazy is a generic lib-rustauth change that needs a release and a pin bump; not worth it before Copilot's first release, recorded for lib-rustauth's next version.
- **Second `sse-stream` version** (part of a low finding): `copilot-providers` uses 0.3 and rmcp 0.2.6. Moving the providers to 0.2 changes the SSE parsing every provider test exercises, for one small crate; not worth the risk before the first release.
- **Existing audio files keep `token_estimate = 0`**: only uploads after this change are measured; a backfill would have to read every stored clip, and chat audio is short-lived context.
