## Decisions

- **One handler for both platforms, by kind only.** Linux needs an answer (WebKitGTK denies without one), and on Android an `Allow` for the microphone still runs the system's runtime prompt (wry asks for the manifest's permissions before granting), so the same answer is right on both. The answer does not look at the page's URL: reading it from the handler goes through Tauri's dispatcher, which is safe on the GTK main thread but not obviously on Android's UI thread, and the web view only ever shows the bundled app (every chat link has `target="_blank"` and opens in the system browser; the CSP allows no remote frames or scripts). P6.1's security review should look at a navigation guard if a page that is not the app could ever load in the main window.
- **Linux grants without a prompt.** WebKitGTK has no prompt of its own (`Default` denies), desktop Linux has no per-app microphone permission outside sandboxes, and the page asks only after a tap on the microphone button, which is the user's consent.
- **Every other kind is denied, including the camera.** The page never asks for video, screens, location, notifications, MIDI, or protected media; denying them keeps a future bug or injected script from using them. On Android `CAMERA` also stays out of the manifest: wry's file chooser then takes photos for an `<input capture>` through the camera app without any permission, while a declared `CAMERA` would add a prompt.
- **The media stream setting is set even though current WebKitGTK has it on.** WebKitGTK 2.52.6 defaults `enable-media-stream` to on (see Verification), but the research note's source documents it as off and older releases may differ. Setting it costs nothing. It must happen in `setup`: there `with_webview` runs synchronously on the main thread right after Tauri creates the window, before the page commits; a change after the page loaded does not reach it.
- **No GStreamer dependency in the `.deb`.** Ubuntu's `libwebkit2gtk-4.1-0` already depends on `gstreamer1.0-plugins-base` and `gstreamer1.0-plugins-good`, and on Ubuntu 24.04 the latter holds the PulseAudio plugin (`libgstpulseaudio.so`; `gstreamer1.0-pulseaudio` is a transitional package), whose source PipeWire desktops serve through `pipewire-pulse`. The AppImage bundles WebKitGTK but not GStreamer's plugins; `bundleMediaFramework` stays off until the device test shows the AppImage cannot record with the system's plugins, because it makes the AppImage much larger.
- **The blocked-microphone advice names the right settings.** In the Android app, "Allow the microphone for this site in the browser's settings" pointed nowhere; after "Don't allow" (twice on recent Android) only Android's app settings can grant it again. The Linux app grants the microphone itself, so its message points at the system's setting.
- **No camera capture yet.** The attach inputs have no `capture` attribute, so Android's picker offers files only. The checklist asks the owner whether a camera button is wanted; it would be a small web change that needs no new permission.
